2) چرا "v4 — Root Cause Fixed"
--------------------------------------------------------------------
هدر فایل به‌طور مفصل توضیح می‌دهد که علت واقعی خالی ماندن داشبورد CEO
در نسخه‌ی قبلی (v3) این بود: `frappe.get_route()` روی یک Workspace
مقدار `["Workspaces", "CEO Dashboard"]` برمی‌گرداند، نه
`["ceo-dashboard"]` — و شرط v3 که `route[0] === "ceo-dashboard"` را
چک می‌کرد همیشه false بود و پنل بلافاصله پس از رندر حذف می‌شد. v4 تابع
current_workspace() را می‌نویسد که:
  - اگر route[0].toLowerCase()=="workspaces" باشد، route[1] را برمی‌گرداند
  - در غیر این صورت با regex روی window.location.pathname پارس می‌کند
    (fallback مبتنی بر URL)
این یک نمونه‌ی عالی از "دیباگ واقعی مبتنی بر Console مرورگر" است که در
کامنت فایل صراحتاً به آن اشاره شده: "ROOT CAUSE FIXED IN v4 (proven
from browser console)".

3) موتور KPI (public/js/ceo_dashboard_kpi.js + api/ceo_kpi.py)
--------------------------------------------------------------------
- سمت سرور (ceo_kpi.py::get_ceo_kpi) یک whitelist method با
  ALLOWED_ROLES محدود (CEO, System Manager, Financial Manager, Finance
  Supervisor, Transport Supervisor) که سه بخش برمی‌گرداند:
    counts: ۷ شمارنده (in_transit, pending_transport, waiting_bijak,
      waiting_clearance, pending_payment, pending_finance, completed,
      total) با یک کوئری SQL تجمیعی (group by workflow_state)
    totals: مجموع tonnage/profit/freight/customs/clearance فقط برای
      Completed
    charts: سه گروه‌بندی (by_border, by_factory, by_customer) با کوئری
      SQL پارامتریک (template فقط از GROUPS ثابت داخل کد ساخته می‌شود،
      نه از ورودی کاربر - جلوگیری از SQL Injection)
- سمت کلاینت: watchdog هر ۱.۵ ثانیه بررسی می‌کند که آیا در صفحه‌ی هدف
  هستیم و پنل وجود ندارد -> رندر می‌کند؛ اگر DOM host هنوز آماده نیست
  تا ۲۴ بار (هر ۲۵۰ms) تلاش مجدد می‌کند. این "polling defensive
  rendering" واکنشی به رفتار غیرقطعی زمان لود Desk SPA فریمورک Frappe
  است.
- تصمیم معماری آگاهانه: "CEO workspace content دیگر بلوک‌های بومی
  number_card/chart را embed نمی‌کند" چون آن ویجت‌ها روی این نصب خالی
  رندر می‌شوند؛ اما اسناد Number Card/Dashboard Chart همچنان در دیتابیس
  و فیکسچر باقی می‌مانند (برای سازگاری آینده اگر باگ فریم‌ورک رفع شد).
- نمودارهای CSS-only (بدون کتابخانه‌ی نمودار) عمداً به‌جای Dashboard
  Chart استاندارد استفاده شده تا "باگ RTL شکل حروف در legend فارسی
  ماژول استاندارد Projects" دور زده شود (نکته‌ی جالب و مستند در
  BACKLOG.md به‌عنوان محدودیت شناخته‌شده‌ی بالادستی).
