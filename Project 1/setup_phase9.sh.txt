3) معماری پلاگین SMS (Adapter Pattern)
--------------------------------------------------------------------
- sms/base_adapter.py::BaseSMSAdapter (ABC): متدهای انتزاعی
  get_config_fields، send_sms، send_bulk_sms (پیش‌فرض حلقه روی
  send_sms)، get_balance، validate_config، test_connection.
  register_adapter(): یک Lazy Proxy که فقط داخل خودش
  adapter_registry.register_adapter را import می‌کند - این طراحی
  عمداً "بدون Circular Import" است (نویسندگان پلاگین از base_adapter
  دکوریتور را می‌گیرند، اما رجیستری واقعی جای دیگری زندگی می‌کند).
- sms/adapter_registry.py: discover_adapters() با os.walk پوشه‌ی
  adapters و importlib.import_module پویا؛ هر خطای import silent-log
  می‌شود (یک آداپتور خراب کل سیستم را نمی‌شکند)؛ get_adapter،
  list_adapters (شامل describe/config_fields هر کلاس).
- دو آداپتور نمونه: generic_http (POST JSON عمومی با هدر Bearer) و
  kavenegar (API واقعی کاوه‌نگار با entries[0].messageid و
  account/info.json برای موجودی حساب).
- sms/sms_service.py::send_sms(): "تنها نقطه‌ی ورود مجاز برای ارسال
  پیامک" (مستند در README.md اپ). هرگز raise نمی‌کند (try/except دور
  کل تابع)، منطق retry با max_retry+retry_delay_seconds، پیشوند
  [TEST→original] در حالت آزمایشی، duplicate guard (alerts/
  duplicate_guard.py::is_duplicate - پنجره‌ی ۱ ساعته، رویدادهای
  sla_breached/sla_critical از این قاعده معاف هستند چون باید بتوانند
  تکرار شوند)، ثبت SMS Alert Log و به‌روزرسانی Notification History
  روی سند مرجع (حتی اگر سند submit شده باشد - با
  ignore_validate_update_after_submit).

4) موتور SLA (sla/sla_monitor.py + sla/escalation_engine.py)
--------------------------------------------------------------------
- check_all_sla(): زمان‌بندی cron هر ۱۵ دقیقه. با
  frappe.utils.scheduler.is_scheduler_inactive() (تأکید صریح در کامنت:
  "is_scheduler_active() DOES NOT EXIST in Frappe v15" - یک باگ واقعی
  کشف‌شده که مستند شده).
  evaluate(elapsed_hours, deadline_hours, warning_threshold_percent):
    normal / warning (>=80% مهلت) / breached (>=100%) / critical
    (>=200%)
  برای هر Transport Case فعال در یک SLA Stage Config، اگر سطح
  warning/breached/critical باشد یک قالب SMS مرتبط پیدا و رندر
  می‌شود و به گیرندگان escalation_engine ارسال می‌شود.
- escalation_engine.py::get_recipients(): برای driver_assigned شماره‌ی
  موبایل خود راننده؛ برای رویدادهای SLA کاربر assigned_user؛ سپس
  Alert Escalation Rule ها بر اساس event_type+level (نقش‌ها یا کاربران
  مشخص) - همیشه Administrator/Guest را فیلتر می‌کند
  (`if user_id in ("Administrator", "Guest"): return None`).

--------------------------------------------------------------------

    کاربر صراحتاً در مورد آن پرسیده بود: URL/lookup داخلی انگلیسی و
    پایدار می‌ماند اما نمایش کاملاً فارسی است چون Frappe سمت UI
    ترجمه‌ی __() را از fa.csv اعمال می‌کند.

    سیستم/کاربران به fa، هرگونه Workspace با نام فارسی

    "IR Gateway" باقی بماند؛ حتی پوشه‌ی روی دیسک با نام فارسی هم حذف
    می‌شود (شواهد این‌که تیم واقعاً این باگ ۴۰۴ را تجربه کرده و برایش
