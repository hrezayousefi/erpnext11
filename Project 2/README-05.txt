۴) تابع واحد و عمومی
----------------------
iran_trade_erp.iran_trade.notification.core.notify(
    event_key, reference_doctype, reference_name, context,
    channels=None, recipients=None, level=None) -> dict

قابل فراخوانی از: هر Workflow Transition | هر Scheduled Job | هر Report |
هر API دلخواه. هیچ وابستگی به نام DocType خاص ندارد (doc_events قفل‌شده حذف شد).

۵) گاردهای مطلق
-----------------
* سند مرجع هرگز save نمی‌شود ⇒ modified و sla_last_action_on دست‌نخورده می‌مانند.
* Administrator/Guest به‌طور مطلق فیلتر می‌شوند.
* نبود گیرنده معتبر ⇒ خطای صریح فارسی در دفتر خطا (بدون بازگشت خاموش).
* نبود قالب برای یک رویداد ⇒ ثبت در دفتر خطا (بدون سکوت).
* کلید عدم تکرار روی UNIQUE INDEX واقعی دیتابیس تکیه دارد.
* Kill-Switch پیش‌فرض خاموش؛ حالت آزمایشی پیش‌فرض روشن.
* هیچ لینک تأیید پیامکی بدون ورود به سیستم وجود ندارد (کاملاً حذف شد).

۶) سطوح تشدید
---------------
سطح ۱ : فقط کارمند مسئول
سطح ۲ : کارمند مسئول + سرپرست مستقیم
سطح ۳ : سرپرست + مدیر واحد (Financial Manager)
سطح ۴ : مدیرعامل (CEO)
همه آستانه‌ها از «تنظیمات درگاه پیامک» خوانده می‌شوند؛ هیچ عدد ثابت در کد.

۱۰) اگر خطا داد
-----------------
- «قالب اعلان یافت نشد» در دفتر خطا → قالب آن event_key را در
  «قالب رویداد اعلان» بسازید. این پیام عمدی است، سکوت ممنوع است.
- ایندکس یکتا ساخته نشد («aborted: duplicates») → رکوردهای تکراری دفتر ارسال را
  پاک کنید سپس install_index.ensure_unique_index را دوباره اجرا کنید.

۱۱) Idempotency / Rollback
----------------------------
قالب‌ها با event_key یکتا به‌روزرسانی می‌شوند. cron تکراری ثبت نمی‌شود.
Rollback: حذف بلوک SCRIPT05 از hooks.py + migrate. برای حذف نمایه:
ALTER TABLE `tabNotification Dispatch Log` DROP INDEX `uq_ite_notif_dedup`;
