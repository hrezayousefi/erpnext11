README-10.txt  —  راهنمای script-10.sh
پذیرش نهایی: اجرای واقعی سه سناریوی کسب‌وکار + ممیزی سراسری G-01..G-20
================================================================================

۱) جایگاه: 09 → [script-10]  (آخرین اسکریپت)
۲) پیش‌نیاز: هر ده فایل قبلی. اسکریپت وجود همه بلوک‌های hooks را ABORT-چک می‌کند.
۳) اجرا:  SITE_NAME=transport-dev.local bash script-10.sh

۴) این اسکریپت هیچ ساختاری نمی‌سازد
-------------------------------------
کارش «اثبات» است نه «ادعا». همه چیز روی سایت زنده و با اعداد واقعی اجرا می‌شود.

۵) سناریوهای اجراشده
----------------------
سناریو الف — خرید کامل:
  ثبت پرونده ۱۰۰ تنی با مدیرعامل دستوردهنده → حقوقی → خزانه → امضا →
  سرپرست مالی → وصول → تاییدشده → ★ صدور ریزفاکتور توسط مالی →
  ★ دریافت توسط حمل → بارگیری → باسکول ۱۰۰ تن → بارنامه (Submit موفق
  توسط کارشناس خرید) → بیجک → ترخیص → رسید تخلیه → پرداخت‌ها →
  چک‌لیست ۱۰ قلمی → بستن → وضعیت «تکمیل‌شده»
  اثبات مالی: بهای عملیاتی = کرایه+گمرک+ترخیص+بیمه (پرداخت‌ها شمرده نشدند)
  اثبات یکسانی: عدد سود در فرم == عدد سود در API

سناریو ب — فروش (الگوی ب: اول فروش، بعد تأمین):
  ثبت پیش‌فروش ۵۰ تنی → ★ پارک در «در انتظار تأمین کالا» →
  اعلان برای مدیرعامل دستوردهنده → آزادسازی → ادامه گردش‌کار → تاییدشده

سناریو ج — ترکیبی/دلالی با ارز مختلط:
  ردیف خرید ریالی + ردیف فروش دلاری در یک پرونده →
  کرایه ریالی + هزینه گمرک دلاری در یک بارگیری →
  اثبات: ارز ویژگی «رویداد» است، نه «پرونده»

سناریو د — کسری تحویل کارخانه:
  ۱۰۰ تن خرید، ۴ تریلی × ۲۴ تن = ۹۶ تن → فاکتور صفر نمی‌شود →
  بستن دستی با دلیل اجباری → ثبت ۴ تن در دفتر بدهی کارخانه →
  گزارش تجمیعی → تسویه بعدی با ارجاع

۷) خروجی
----------
گزارش پذیرش در:
  sites/<SITE_NAME>/private/files/ITE_ACCEPTANCE_REPORT.txt
سپس هر ده Verify فاز قبل دوباره اجرا می‌شوند تا Idempotency و سلامت کل
سیستم هم‌زمان اثبات شود.

۸) اگر خطا داد
---------------
- «acceptance FAILED: n مورد رد شد» → فایل ITE_ACCEPTANCE_REPORT.txt را باز
  کنید؛ هر سطر با [رد] دقیقاً می‌گوید کدام گزاره اثبات نشده است.
- «ABORT: ... موجود نیست» → اسکریپت‌های ۰۱ تا ۰۹ را به ترتیب اجرا کنید.

۹) Idempotency
----------------
اجرای دوباره، پرونده‌های آزمایشی جدید می‌سازد اما هیچ داده قبلی را خراب
نمی‌کند و هیچ ساختاری را تغییر نمی‌دهد. کلیدهای یکتای عملیات از ثبت دوباره
بارگیری‌های آزمایشی جلوگیری می‌کنند.
