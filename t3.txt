# ۴) چرا پروژه‌های اول و دوم شکست خوردند

مشکل اصلی Frappe نبود.

مشکل اصلی این بود:

```text
AI writes code
      ↓
AI writes test for same code
      ↓
test uses Administrator / ignore_permissions
      ↓
PASS
      ↓
browser with real user
      ↓
FAIL
      ↓
patch
      ↓
old behavior breaks
      ↓
new patch
      ↓
repeat
```

این یعنی:

> **سیستم از دید برنامه‌نویس سبز بود، ولی از دید انسان قرمز بود.**

حتی در پروژه‌های قبلی شواهد این روش وجود دارد؛ برای مثال تست‌های عملیاتی با `save(ignore_permissions=True)` اجرا می‌شدند، در حالی که آنچه باید ثابت شود این بود که همان کار برای کاربر واقعی مجاز است. 

در نسخه دوم بعضی جاها این مشکل بهتر شده بود و حتی برای `Customer` و `Company` و `Version` و `Driver` از `frappe.has_permission(..., user=...)` استفاده شد؛ این قسمت باید حفظ شود. 

اما هنوز یک اشکال روش‌شناختی پابرجاست:

```text
وجود DocType =/= قابل استفاده بودن
وجود Workflow =/= اجرای Workflow
وجود Permission Row =/= دسترسی کاربر
وجود API =/= مسیر انسانی
PASS verify =/= موفقیت واقعی
```

* migrate
